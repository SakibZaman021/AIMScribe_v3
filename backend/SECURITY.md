# Security Policy

AIMScribe records clinical consultations. The threat that matters is not an
outage — it is a recording that is silently wrong, missing, or attributed to the
wrong doctor, hospital or patient.

## Reporting a vulnerability

Report privately to the AIMS LAB team. **Do not open a public issue**, and do not
include patient identifiers, tokens, keys or recordings in a report.

Include what you did, what happened, and what you expected. You should get an
acknowledgement within a few working days.

## Supported versions

| Component | Supported |
|---|---|
| Backend `main` | Yes |
| Agent 2.3.x (protocol 2) | Yes |
| Agent 2.0–2.2 | Security fixes only; upgrade |
| Anything protocol 1 | **No.** Superseded and structurally insecure |

Protocol 1 let the browser name its own hospital and had no authentication on
any route. It is not supported and must not be redeployed.

In particular, the protocol-1 AIMS LAB upload server — an unauthenticated
`POST /receive-recording` bound to `0.0.0.0:7000` — was removed in July 2026 and
replaced by the outbound-only `archive_worker/`. An old working copy may still
contain it. It must never be run: it accepts audio from anyone who can reach the
port, enumerates patient identifiers over `GET /patients`, and writes outside the
archive tree, where nothing is covered by the hash chain or purge receipts.

## What the system enforces

- Every `/api/v2` route requires a credential; sessions are scoped to the device
  that opened them.
- Uploaded objects are re-read from storage and re-hashed server-side at commit.
  A client's claim about what it uploaded is never trusted.
- Each session carries an Ed25519 hash chain signed by a machine-bound device
  key, verified on the server at close. A broken chain quarantines the session.
- Local audio is deleted only against a signed purge receipt proving a verified
  archive copy exists — never because an upload returned HTTP 200.
- `audit_log` is append-only, enforced by a database trigger.
- Enrolment tokens are single-use, hospital-bound, expiring, and stored only as
  SHA-256. The plaintext is never persisted.
- Recording requires a CMED-signed, single-use, 60-second EdDSA grant. Only
  `EdDSA` is accepted, which defeats `alg: none` and HMAC confusion.
- The agent's local socket accepts only exact configured origins and hosts.
- The archive worker accepts no inbound connections and holds no bucket
  credentials.

## Known gaps

Tracked and disclosed deliberately:

- `/api/v1` routes are unauthenticated.
- `AIMSCRIBE_WEBHOOK_SECRET` is hardcoded and needs rotating.
- `D:\AIMSLAB_AUDIO_STORAGE` has no backup.
- Agent binaries are not yet Authenticode-signed.

## Handling secrets

**This repository is public.** No key, token, connection string or password
belongs in it. `.env` is gitignored; production values live in the Render
dashboard.

Enrolment token sheets generated by `scripts/mint_enrolment_tokens.py` are
credentials. Keep them out of version control and delete them once the machines
are installed.

If a secret is committed, rotate it — removing the commit is not sufficient.

## Patient data

Recordings and transcripts contain patient data. Do not attach them to issues,
paste them into logs, or copy them to machines outside the archive. Agent logs
redact identifiers by default (`AIMS_REDACT_LOGS=true`); leave it on.
